# Changelog

All notable changes to `@coggit/cli` are documented here. Format follows
[Keep a Changelog](https://keepachangelog.com/); versioning is semver.

## [0.5.1] - 2026-11-03

### Added

- `coggit skills` — locates the agent skill that now ships with the package
  (`skills/coggit/`, a dispatch SOP for CLI agent hosts: the set-up / author
  / maintain command sequences, pointing back to `coggit entry`, `--help`,
  and `coggit handbook` for stance, mechanics, and authoring rules). The
  tree is multi-file and split by use temperature: SKILL.md carries the
  everyday loop (orient / author / maintain) plus the standard payload core
  (install unit + consent boundary + canon-site pointer);
  `skills/coggit/references/setup.md` carries the one-time operations (the
  project set-up dance and the post-upgrade guidance refresh); and
  `skills/coggit/references/payload.md` carries the full install/refresh
  reconciliation contract (version stamps, frontmatter ownership, conflict
  handling). The SKILL.md frontmatter is pure key-value with zero comments,
  and its description is the bare manual marker (`manually — …`): a by-name
  skill has no auto-trigger reader; the name is the trigger word. The
  command only announces where the tree is (`--json`: `name`, `version`,
  `skillRoot`, `skillMd` — additive-only) and never writes an agent
  directory; copying or linking the tree is the agent's move. A linked
  development install announces the working tree it follows.

## [Unreleased]

### Changed

- The stance's delivery splits into a paste-once ambient layer and an
  on-demand full stance: the AGENTS.md block is now the default
  `minimal` kind — an invariant block (entry + orientation + fetch pointer
  over the identity/ordering/upkeep body) pasted once and never re-pasted;
  stance wording evolution reaches agents through the block's fetch pointer
  (`coggit entry --kind standard`), not through re-pasting. The orientation
  sentence now rides `minimal` as well (supersedes the 2026-10-08
  entry-only ruling), and the `entry` help recommendation flips
  accordingly. `--kind standard` raw/block output is byte-identical to
  0.5.1; existing standard-shaped blocks keep working.


## [0.5.0] - 2026-11-01

### Changed

- Every CLI surface that names the handbook now spells where it lives on
  a CLI host — `coggit handbook <kind>`: the standard prompt's delegation
  segment, the status action legend, and the add success line previously
  referenced the handbook without a CLI address (the MCP and dsh surfaces
  already carried their own spellings).
- Lockstep with the 0.5.0 wave: the CLI's file visibility rides
  `@coggit/core`'s source-exclusion engine swap — see the core changelog
  for the semantics.

## [0.4.0] - 2026-10-17

### Removed

- **Breaking:** the `coggit instructions` command spelling — the guidance
  command is now `coggit entry` only, the ecosystem convention name for
  entry-type commands (self-describing, context-free, idempotent stdout;
  generic tool-entry hosting). No compatibility alias. Arguments and
  options are unchanged (`[kind]` positional synonym, `--kind`,
  `--format`). The managed block's guardrail notice now names
  `coggit entry` as the re-run command — blocks generated by earlier
  releases teach the removed spelling, so hosts re-generate on upgrade.

## [0.3.0] - 2026-10-08

### Changed

- `coggit instructions --kind standard`: the composite now carries a second
  access sentence — "Orient with `coggit status`: the header names the
  source and cognition roots, and `coggit status <path>` names a file's
  paired cognition document." — so the first orientation questions are
  answered with the commands that answer on the CLI text surface
  (`CLI_STANDARD_ORIENTATION_SENTENCE`; `minimal` stays entry-only, its
  orientation weakness addressed by the prefer-standard install guidance
  below).
- Help face: `status`, `snapshot`, `add`, `resolve`, and `handbook` now
  carry description lines at registration. The descriptions carry
  decision-relevant semantics: `handbook` glosses the kinds (leaf = a
  source file's paired cognition document, skeleton = a folder's paired
  README cognition — previously prior-knowledge-only), `add --kind` glosses
  `auto` (file to leaf, folder to skeleton), and `instructions`' description
  states the install preference rule — persistent guidance (an AGENTS.md
  block) should prefer `--kind standard`; the default `minimal` suits
  per-invocation composition.
- `coggit instructions --format block`: the managed block now opens with a
  guardrail notice — "generated by `coggit instructions`; do not hand-edit.
  To update, re-run `coggit instructions --kind <kind> --format block` and
  replace this whole block (markers included)" — so the replace-not-append
  update move travels with the artifact instead of living only in owner
  docs (`blockManagementNotice()`; `raw` is unchanged).

- `coggit status` text output: a missing cognition pair now prints the
  derivable cognition path — `Cognition: src_cognition/foo.ts.md (not
  created; add on demand)` — instead of the bare `Not created (add on
  demand)`, so the cognition root is named on every status call (core
  `describeMissingCognition()`).

### Removed

- `coggit routes` command — the `routes` operation is retired from CogGit
  entirely (navigation is not part of the pair-maintenance core).
  Orient with `coggit snapshot` or the mirror convention instead.

### Added

- `coggit -v` / `coggit --version`: print the CLI version (wires the
  `__COGGIT_PACKAGE_VERSION__` build macro into commander's `.version()`).

### Fixed

- `coggit instructions` silently ignored a positional kind argument —
  `coggit instructions standard` printed the default minimal form with no
  signal. The positional now works as a synonym of `--kind`; a positional
  that conflicts with an explicit `--kind` is a user error (exit 1).

## [0.2.1] - 2026-09-05

Patch release exercising the tag-triggered publish workflow (first CI
publish; no functional changes).

## [0.2.0] - 2026-09-05

Initial npm publish (`npm i -g @coggit/cli`; the `coggit` bin name is
unchanged — the unscoped `coggit` registry name was rejected as too similar
to the existing `cz-git` package). `0.2.0` matches the monorepo split
source; there is no npm release for `0.1.0`.

### Added

- `coggit` bin: source/cognition freshness status, snapshot, routes, and MCP
  install from the command line.
- Consumes the published SDK (`@coggit/core` + `@coggit/runtime-node`) as real
  registry dependencies; internal helpers (`format`, `mcp-runtime-support`)
  and `commander` are bundled — no private packages in the dependency tree.
